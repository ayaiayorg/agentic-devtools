# Implementation Plan: SpecKit Markdown Rules for Fenced Code Blocks

## Technical Context

- **Stack**: SpecKit prompt system — Markdown-based command templates (`.specify/templates/commands/*.md`), Copilot agent files (`.github/agents/speckit.*.agent.md`), and bash/PowerShell pipeline
  scripts (`.specify/scripts/`)
- **Inclusion pattern**: Templates already use `/memory/constitution.md` as a virtual path (command templates) and `.specify/memory/constitution.md` as a filesystem path (agent files). This
  establishes the precedent.
- **Pipeline scripts**: `update-agent-context.sh` / `.ps1` are the runtime prompt assembly scripts — they read templates, substitute placeholders, and write agent context files.
- **Python runtime**: `agentic_devtools/prompts/loader.py` handles Jinja2-based prompt assembly for agdt workflows — **not in scope** (serves agdt workflows, not SpecKit).

## Research Summary

See [research.md](research.md) for detailed analysis. Key decisions:

1. **Shared file location**: `.specify/memory/markdown-rules.md` (spec decision #1)
2. **Virtual path**: `/memory/markdown-rules.md` in command templates; `.specify/memory/markdown-rules.md` in agent files (mirrors constitution pattern)
3. **Inclusion line format**: Natural-language load verb matching existing constitution references
4. **Pipeline injection**: `cat` + shell variable in bash; `Get-Content` in PowerShell
5. **Placement**: In the context-loading step of each template, before generation instructions begin
