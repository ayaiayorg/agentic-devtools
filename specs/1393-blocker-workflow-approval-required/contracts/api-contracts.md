## GitHub REST API Endpoints Used

### 1. List Workflow Runs

**Endpoint**: `GET /repos/{owner}/{repo}/actions/workflows/{workflow_id}/runs`

**Purpose**: Find runs of the lint workflow that have `conclusion: action_required`.

**Parameters**:

| Parameter | Value | Description |
|-----------|-------|-------------|
| `workflow_id` | `ai-pr-loop-lint.yml` | Target the specific lint workflow |
| `status` | `completed` | Filter to completed runs (approval-gated runs are marked completed with conclusion=action_required) |
| `per_page` | `10` | Limit results (recent runs only) |

**Response fields used**:

- `workflow_runs[].id` — Run ID for approval
- `workflow_runs[].conclusion` — Filter for `"action_required"`
- `workflow_runs[].head_sha` — For retry tracking
- `workflow_runs[].pull_requests[].number` — Associated PR number
- `workflow_runs[].actor.login` — Run trigger actor (workflow metadata only; **not** the PR author — use `GET /pulls/{pull_number}` and `user.login` for author verification)

---

### 2. Approve Workflow Run

**Endpoint**: `POST /repos/{owner}/{repo}/actions/runs/{run_id}/approve`

**Purpose**: Programmatically approve a pending workflow run.

**Authentication**: `COPILOT_GITHUB_TOKEN` with Actions write permission (fine-grained PAT: **Actions → Read and write**; classic PAT: `workflow` scope).

**Request**: Empty body.

**Response**:

| Status | Meaning |
|--------|---------|
| `201 Created` | Run approved successfully |
| `403 Forbidden` | Token lacks Actions write permission |
| `404 Not Found` | Run does not exist or is not in approval-pending state |
| `409 Conflict` | Run is not in a state that can be approved |

---

### 3. Get Pull Request Details

**Endpoint**: `GET /repos/{owner}/{repo}/pulls/{pull_number}`

**Purpose**: Verify PR author is in the trusted bot accounts list.

**Response fields used**:

- `user.login` — PR author username (checked against allow-list)
- `head.sha` — Current head SHA (for retry marker matching)
- `head.repo.full_name` — Verify same-repo (not fork)
- `base.repo.full_name` — Compare with head repo

---

### 4. List PR Comments (for retry markers)

**Endpoint**: `GET /repos/{owner}/{repo}/issues/{issue_number}/comments`

**Purpose**: Find existing retry marker comments to determine current attempt count.

**Response fields used**:

- `body` — Parse for `<!-- workflow-approval-retry:{sha}:{count} -->` marker
- `id` — Comment ID for updating existing marker

---

### 5. Create/Update PR Comment

**Endpoint**: `POST /repos/{owner}/{repo}/issues/{issue_number}/comments`
or `PATCH /repos/{owner}/{repo}/issues/comments/{comment_id}`

**Purpose**: Post or update retry tracking comment and failure notification.

**Request body**:

```json
{
  "body": "<!-- workflow-approval-retry:{sha}:{count} -->\n## ⚠️ Workflow Approval Failed\n\n..."
}
```

---

### 6. Get Repository Content (Config File)

**Endpoint**: `GET /repos/{owner}/{repo}/contents/.github/ai-pr-loop-config.json`

**Purpose**: Read the trusted bot accounts configuration.

**Response**: Base64-encoded file content (decode and parse as JSON).

## Error Handling Contract

| Scenario | Response | Monitor Action |
|----------|----------|----------------|
| Run already approved | 404 or 409 from approve endpoint | Log skip; continue (idempotency per FR-008) |
| Token permission denied | 403 from approve endpoint | Log failure; increment retry count |
| Run not found | 404 from runs endpoint | Log skip; no action |
| Config file missing | 404 from contents endpoint | Log error; abort (cannot determine trusted accounts) |
| Rate limit exceeded | 403 with `X-RateLimit-Remaining: 0` | Log warning; exit early (next schedule will retry) |
