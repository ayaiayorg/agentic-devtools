# Quickstart: Workflow Approval Monitor

**Issue**: [#1393](https://github.com/ayaiayorg/agentic-devtools/issues/1393)

---

## Prerequisites

- Repository admin access (for settings change)
- `COPILOT_GITHUB_TOKEN` secret with Actions write permission (fine-grained PAT: **Actions → Read and write**; classic PAT: `workflow` scope)
- GitHub Actions enabled on the repository

---

## Step 1: Configure Repository Settings (FR-001/FR-002)

1. Navigate to **Settings → Actions → General**
2. Under "Fork pull request workflows from outside collaborators", select:
   **"Require approval for first-time contributors"**
3. This allows recognized collaborators (and same-org GitHub App installations) to run
   workflows without manual approval.

> **Note:** If the org policy overrides this setting, the programmatic approval fallback
> (Step 3) will activate automatically.

---

## Step 2: Create the Config File (FR-007)

Create `.github/ai-pr-loop-config.json`:

```json
{
  "trusted_bot_accounts": [
    "copilot-swe-agent[bot]",
    "github-actions[bot]"
  ]
}
```

---

## Step 3: Deploy the Approval Monitor (FR-003/FR-004)

The `workflow-approval-monitor.yml` workflow will be created in
[Phase 2 (P2) — Approval Monitor Workflow](plan.md#phase-2--approval-monitor-workflow-p2--fr-003-fr-004-fr-005-fr-007-fr-008)
of the implementation plan.
Once deployed, it:

- Runs every 2 minutes via cron schedule
- Detects workflow runs stuck in `action_required` state
- Auto-approves runs from trusted bot accounts
- Posts a PR comment after 3 failed attempts (NFR-006)

---

## Step 4: Verify the Dispatch Pre-Check (FR-009)

The pre-check guard in `ai-pr-loop.yml` ensures the dispatch-decision step skips
processing when the triggering lint run is still awaiting approval. No manual
configuration is needed — it activates automatically via the `workflow_run` event payload.

## Troubleshooting

| Symptom | Cause | Resolution |
|---------|-------|------------|
| Lint workflow still requires approval after settings change | Org policy overrides repo setting | Rely on programmatic approval (monitor workflow) |
| Monitor workflow fails to approve | `COPILOT_GITHUB_TOKEN` missing Actions write permission | Update PAT permissions (fine-grained: Actions → Read and write; classic: `workflow` scope) |
| Monitor runs but finds no stuck runs | Approval-gated runs have `status: completed` with `conclusion: action_required` (not a distinct `status` value) | Ensure the API query filters by `status=completed` and then checks `conclusion === 'action_required'` client-side; see [API Query Strategy](plan.md#api-query-strategy) |
