**Issue**: [#1393](https://github.com/ayaiayorg/agentic-devtools/issues/1393)

## Configuration Schema

### `.github/ai-pr-loop-config.json`

```json
{
  "trusted_bot_accounts": ["copilot-swe-agent[bot]", "github-actions[bot]"]
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `trusted_bot_accounts` | string[] | Yes | List of GitHub account names eligible for auto-approval |

### Validation Rules

- `trusted_bot_accounts` must be a non-empty array of strings
- Each entry must be an exact GitHub username (no wildcards, no regex)
- Comparisons are **case-insensitive**: both config entries and the PR author login
  (`pulls.user.login`) are normalized to lowercase before matching
  (GitHub usernames are effectively case-insensitive)
- Allow-list matching is performed **solely against the PR author** —
  `actor.login` (the account that triggered the workflow run) is not used for
  trust decisions, as it may differ from the PR author; it is recorded in
  audit log entries as metadata only

## Audit Log Entry Schema

Emitted by the approval monitor workflow via `core.info()` (FR-005):

```json
{
  "event": "workflow_approval",
  "actor": "workflow-approval-monitor",
  "timestamp": "2026-05-11T14:30:00Z",
  "pr_number": 1234,
  "run_id": 56789,
  "head_sha": "abc1234def5678",
  "source": "programmatic",
  "result": "success",
  "reason": null
}
```

| Field | Type | Description |
|-------|------|-------------|
| `event` | string | Always `"workflow_approval"` |
| `actor` | string | Always `"workflow-approval-monitor"` |
| `timestamp` | string (ISO-8601) | UTC timestamp of the action |
| `pr_number` | integer | PR number associated with the stuck run |
| `run_id` | integer | Workflow run ID that was approved/skipped |
| `head_sha` | string | Commit SHA of the PR head at approval time |
| `source` | string | `"programmatic"` for API approval, `"manual"` for human approval |
| `result` | string | `"success"`, `"failure"`, or `"skipped"` |
| `reason` | string or null | Reason for failure/skip (null on success) |

## Retry Tracking (PR Comment Markers)

HTML comment markers embedded in PR comments to track retry state:

```text
<!-- workflow-approval-retry:{sha}:{count} -->
```

| Field | Type | Description |
|-------|------|-------------|
| `sha` | string | Full commit SHA of the PR head |
| `count` | integer | Number of approval attempts made (max: 3 per NFR-006) |

### State Transitions

```text
No marker exists     → First attempt (count=1)
count=1              → Second attempt (count=2)
count=2              → Third attempt (count=3)
count=3              → Stop retrying; post failure comment
```

## GitHub API Entities

### Workflow Run (relevant fields)

Returned by `GET /repos/{owner}/{repo}/actions/runs`:

| Field | Type | Relevance |
|-------|------|-----------|
| `id` | integer | Run ID for approve API call |
| `status` | string | Run execution status (`completed`, `in_progress`, etc.) |
| `conclusion` | string or null | Run outcome (`action_required`, `success`, `failure`, etc.) |
| `head_sha` | string | Commit SHA — used for retry tracking |
| `event` | string | Trigger event (`pull_request`, `push`, etc.) |
| `pull_requests` | array | Associated PRs (may be empty for some triggers) |
| `actor.login` | string | Account that triggered the run |

### Key Relationships

```text
Workflow Run
  ├── has conclusion: "action_required" (gated, needs approval)
  ├── belongs to: Workflow (ai-pr-loop-lint.yml)
  ├── triggered by: PR event (pull_request: synchronize/opened)
  └── associated with: Pull Request
        └── authored by: Bot Account (in trusted_bot_accounts list)
```
