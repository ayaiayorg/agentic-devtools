# Data Model: PR review scaffolding 403 cross-identity recovery

## Entities

### FileEntry (`review-state.json`)

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `path` (map key) | `str` | required | Repository-relative path stored as key in `ReviewState.files` |
| `threadId` | `int` | required | Existing scaffold thread ID |
| `commentId` | `int` | required | Existing scaffold comment ID |
| `folder` | `str` | required | Derived folder grouping |
| `fileName` | `str` | required | Basename for display |
| `status` | enum | required | Existing review lifecycle status |
| `crossIdentity` | `bool` | `false` | True when recovered thread owner differs from current identity |

### IdentitySnapshot

| Field | Type | Source |
|-------|------|--------|
| `id` | `Optional[str]` | Azure DevOps `_apis/connectionData.authenticatedUser.id` |
| `uniqueName` | `Optional[str]` | Azure DevOps `_apis/connectionData.authenticatedUser.uniqueName` (fallback matching only) |
| `displayName` | `Optional[str]` | Azure DevOps `_apis/connectionData.authenticatedUser.providerDisplayName` (fallback `customDisplayName`) for user-facing attribution |

## Behavioral Rules

- Recovery compares `comments[0].author.id` to cached identity `id`.
- Fallback comparator uses `uniqueName` only when `author.id` is missing.
- Missing `crossIdentity` in existing state files deserializes as `false`.
