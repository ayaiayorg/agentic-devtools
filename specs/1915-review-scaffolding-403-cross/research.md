# Research: PR review scaffolding 403 cross-identity recovery

## Sources Reviewed

- `spec.md` clarification decisions (identity endpoint, fallback behavior, timeout scope)
- Existing Azure DevOps identity paths in `agentic_devtools/cli/azure_devops/finalization/identity.py`
- Existing review scaffolding update paths in `review_scaffold.py` and `helpers.py`

## Key Findings

1. Identity resolution should reuse the existing `_apis/connectionData` path instead of introducing parallel resolver logic.
2. Cross-identity update fallback should preserve full scaffold content by posting a reply in the existing thread.
3. Batch submission must isolate per-thread failures so one forbidden update does not abort the full cascade.
4. Timeout applies to batch submission only, with a default budget of 120 seconds.

## Implementation Direction

- Extend shared identity utilities and consume from review scaffolding recovery.
- Introduce a typed 403 exception path (`CrossIdentityForbiddenError`) to trigger reply fallback.
- Keep backward compatibility for `review-state.json` by defaulting `crossIdentity` to `false`.
