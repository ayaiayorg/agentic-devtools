# Feature Specification: Standardize Copilot Review PR Response Process

**Feature Branch**: `speckit/1432/phase-1-specify`
**Created**: 2026-05-15
**Status**: Draft
**Source Issue**: #1432 (<https://github.com/ayaiayorg/agentic-devtools/issues/1432>)

## Problem Statement

Currently, the process for responding to Copilot PR reviews uses custom methods for starting
Copilot CLI sessions, and logic for triggering/finalizing the loop is scattered across workflow
YAMLs and Python modules. Suppressed Copilot PR comments require manual intervention and are
easy to miss. The system needs a fully automated, platform-agnostic PR loop using GitHub Actions
(no agent) where non-trivial logic resides in the agentic-devtools Python codebase.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Automated AI Session Trigger (Priority: P1)

As a repository maintainer, I want the system to automatically post a PAT-authenticated PR
comment tagging @copilot when both the Copilot review and PR checks have completed, so that
the AI agent session is triggered without manual intervention.

**Why this priority**: This is the entry point for the entire automated loop — nothing else
can proceed without a reliable trigger mechanism.

**Independent Test**: Can be tested by simulating a completed Copilot review + completed PR
checks and verifying that a correctly formatted @copilot comment is posted to the PR.

**Acceptance Scenarios**:

1. **Given** a Copilot review has completed AND all PR checks have completed, **When** the
   workflow runs, **Then** a PAT-authenticated comment beginning with @copilot is posted to
   the PR using the appropriate template.
2. **Given** only the Copilot review has completed but PR checks are still pending, **When**
   the workflow evaluates, **Then** no comment is posted until checks also complete.
3. **Given** suppressed Copilot review comments exist, **When** the trigger fires, **Then**
   the comment uses the `pr_review_process.md` template and includes the suppressed comments.
4. **Given** no suppressed comments exist, **When** the trigger fires, **Then** the comment
   uses the `ci_review_process.md` template with links to any failing checks and logs.

### User Story 2 - Automatic Thread Resolution (Priority: P1)

As a repository maintainer, I want the system to automatically reply to every Copilot review
comment and resolve those threads after the AI agent session completes, so that resolved
feedback is cleaned up without manual work.

**Why this priority**: Thread resolution is critical for maintaining a clean PR state and
enabling re-review cycles.

**Independent Test**: Can be tested by verifying that after the agent result comment appears,
all Copilot review threads receive a reply linking to the result and are resolved.

**Acceptance Scenarios**:

1. **Given** the AI agent session has completed and posted its result comment, **When** the
   resolution step runs, **Then** every comment from the Copilot review receives a reply
   linking to the agent's summary/result comment.
2. **Given** replies have been posted, **When** the resolution step completes, **Then** all
   corresponding review threads are resolved via the GitHub GraphQL API.
3. **Given** a thread resolution fails, **When** the system retries, **Then** it retries up
   to 3 times before reporting the failure.

### User Story 3 - Commit Squash with SDK-Generated Message (Priority: P1)

As a repository maintainer, I want PR commits to be squashed into a single commit with a
message generated by the Copilot SDK (following `commit_convention.md`), so that Copilot
review can be re-triggered on a clean single-commit state.

**Why this priority**: Copilot review cannot be re-invoked via PAT — squashing commits and
re-requesting review is the only path to get a fresh review cycle.

**Independent Test**: Can be tested by verifying that after the agent adds commits, the
system squashes all PR commits into one and the commit message follows the conventions in
`commit_convention.md`.

**Acceptance Scenarios**:

1. **Given** the AI agent session has added one or more commits to the PR, **When** the
   squash step runs, **Then** all PR commits are squashed into a single commit.
2. **Given** commits are being squashed, **When** the commit message is generated, **Then**
   the Copilot SDK is called with the full PR changes/diff and `commit_convention.md` to
   produce the message.
3. **Given** the squash is complete, **When** Copilot review is re-requested, **Then** the
   new single commit triggers a fresh Copilot review.

### Edge Cases

- What happens when the Copilot review completes before PR checks, then checks fail later
  and are re-run? The system must wait for the final check state before triggering.
- What happens when the AI agent session fails to produce a result comment? The system must
  time out and report the failure rather than waiting indefinitely.
- What happens when suppressed comments span multiple review submissions? Only comments from
  the current review cycle should be included.
- What happens when the PAT lacks sufficient permissions? The system must fail gracefully
  with a clear error message indicating the missing permission.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The system MUST post a PAT-authenticated PR comment beginning with @copilot
  when both Copilot review and PR checks have completed.
- **FR-002**: The system MUST NOT post a trigger comment if either Copilot review or PR
  checks are still pending.
- **FR-003**: The trigger comment MUST use the `pr_review_process.md` template when
  suppressed Copilot review comments exist.
- **FR-004**: The trigger comment MUST use the `ci_review_process.md` template when no
  suppressed comments exist.
- **FR-005**: The trigger comment MUST include direct links to any failing PR checks and
  their logs.
- **FR-006**: The @copilot tag MUST appear at the very beginning of the comment body (not
  embedded within quoted text or other content).
- **FR-007**: After the AI agent session completes, the system MUST reply to every comment
  from the Copilot review with a link to the agent's result comment.
- **FR-008**: After replies are posted, the system MUST resolve all corresponding review
  threads via the GitHub GraphQL API.
- **FR-009**: After thread resolution, the system MUST squash all PR commits into a single
  commit.
- **FR-010**: The squashed commit message MUST be generated by the Copilot SDK with full PR
  diff context and adherence to `commit_convention.md`.
- **FR-011**: After squashing, the system MUST re-request Copilot review on the PR.
- **FR-012**: The system MUST detect and prevent duplicate trigger comments for the same
  review cycle.
- **FR-013**: All non-trivial logic MUST reside in the agentic-devtools Python codebase,
  not in workflow YAML.
- **FR-014**: The system MUST detect the AI agent's result comment by monitoring PR
  comments after the trigger.
- **FR-015**: The system MUST support both the suppressed-comments template and the
  CI-only template selection automatically based on review state.

### Non-Functional Requirements

- **NFR-001**: The end-to-end loop (from trigger to re-review request) MUST complete
  within 10 minutes for a typical PR (excluding external API latency and agent execution
  time).
- **NFR-002**: The system MUST retry failed GitHub API calls up to 3 times with
  exponential backoff.
- **NFR-003**: All new code MUST have unit tests following the 1:1:1 test structure
  policy with 100% coverage.
- **NFR-004**: The system MUST be idempotent — re-running the workflow for the same state
  produces no duplicate side effects.
- **NFR-005**: The system MUST log structured audit events for each major step (trigger,
  reply, resolve, squash, re-request) for observability.
- **NFR-006**: Workflow YAML MUST contain only orchestration (job definitions, step
  sequencing, secret injection) with no business logic.
- **NFR-007**: The system MUST produce clear, actionable error messages when a step fails
  (including the specific API error and suggested remediation).

### Key Entities

- **Review Cycle**: A single Copilot review submission and the subsequent automated
  response loop.
- **Trigger Comment**: The PAT-authenticated PR comment that invokes the AI agent session.
- **Result Comment**: The comment posted by the AI agent session summarizing its actions.
- **Review Thread**: A GitHub PR review discussion thread associated with a specific
  comment.
- **Template**: A markdown template (`pr_review_process.md` or `ci_review_process.md`)
  defining the trigger comment format.

## Clarifications

1. **Agent result detection**: The system detects the AI agent's result comment by
   monitoring PR comments posted after the trigger, filtering by the agent's bot identity
   and expected comment structure.
2. **Template location**: Templates are stored in the repository wiki and referenced by
   the workflow. The Python code loads templates at runtime for comment generation.
3. **Copilot SDK for commit messages**: The Copilot SDK is invoked with the full PR diff,
   the commit convention specification, and PR context to generate a meaningful
   conventional commit message for the squashed commit.

## Assumptions

- GitHub Actions has access to a PAT with sufficient permissions (write access to PRs,
  issues, and actions).
- The Copilot review bot and the AI agent bot are distinct identities that can be
  differentiated by their login names.
- The `pr_review_process.md` and `ci_review_process.md` templates exist in the repository
  wiki and follow a stable format.
- Copilot review can be re-triggered by requesting it as a reviewer after a force-push.

## Dependencies

- GitHub Actions workflow infrastructure with PAT secret configuration.
- GitHub REST API and GraphQL API for PR operations.
- Copilot SDK for commit message generation.
- Existing `agdt-gh-*` commands for thread resolution and review requests.
- Repository wiki templates for comment formatting.

## Out of Scope

- Azure DevOps platform adapter (future work — this spec covers GitHub only).
- Modifying how the AI agent session itself operates (the agent is treated as a black box).
- Changing existing `agdt-*` CLI command signatures or behavior.
- Handling fork PRs (only same-repo PRs are in scope).
