# Research: PR Review Workflow State Directory Mismatch

**Issue**: #1913 | **Branch**: `speckit/1913/phase-3-plan` | **Spec**: [spec.md](spec.md)

## 1. Root Cause Analysis

The state directory mismatch occurs because the cross-worktree workflow has three separate execution stages, each resolving the state directory independently:

### Stage 1 — Source repo invocation (`agdt-initiate-*-workflow`)

- User runs the workflow initiation command from the **source repository**.
- `commands.py` writes the pin file to the *source* repository's `.agdt/` directory.
- During normal initiation, `commands.py` resolves the canonical state directory and sets
  `os.environ["AGENTIC_DEVTOOLS_STATE_DIR"]` via `env_override`, so child/background
  processes inherit that value unless they explicitly clear or override it.

### Stage 2 — Auto-execute subprocess (`_run_auto_execute_command`)

- `worktree_setup.py` spawns a subprocess that re-runs the workflow init inside the **target worktree**.
- Before spawning, it sets `env["AGENTIC_DEVTOOLS_STATE_DIR"]` to the resolved canonical state path.
- However, it does **not** write a pin file to the target worktree's `.agdt/` directory.
- The subprocess uses `AGENTIC_DEVTOOLS_STATE_DIR` from the environment variable.

### Stage 3 — VS Code auto-start (`copilot_auto_start_cmd`)

- VS Code fires the `runOn: folderOpen` task in the **target worktree** context.
- `copilot_auto_start_cmd` explicitly **clears** `AGENTIC_DEVTOOLS_STATE_DIR` before resolving state.
- `get_state_dir()` falls through resolution order: env var (cleared) → pin file → bootstrap → fallback.
- With no pin file in the target worktree, resolution reaches bootstrap-based paths, which may resolve a **different physical directory** (e.g., `C:\repos\DFLYP-5279\` instead of `C:\repos\dfly-platform-management\`).

Two different repository roots for the same workflow run → state written by auto-execute is invisible to the first Copilot session.

### Pin file resolution order (`get_state_dir()`)

1. `AGENTIC_DEVTOOLS_STATE_DIR` env var (cleared by auto-start)
2. `.agdt/pinned-state-dir.json` (not written to target worktree — **the gap**)
3. `runtime-bootstrap.json` (may reference source repo root)
4. `_unscoped` fallback
5. `.agdt-temp/` under CWD when no git root is available

## 4. Decision: Leverage Existing Pin File Mechanism

Rather than introducing a new state handoff mechanism, the fix extends the existing `pinned-state-dir.json` mechanism introduced by #1180:

- `write_pin_file()` gains an optional `target_git_root` parameter so callers can write the pin to an explicit git root.
- `_run_auto_execute_command()` calls `write_pin_file()` with `target_git_root=Path(worktree_path)` after resolving the state directory, before spawning the subprocess.
- `RECOGNIZED_PIN_WORKFLOWS` is expanded to include all workflows that use `_run_auto_execute_command`.

This preserves the existing TTL, cleanup, and validation contracts. See [plan.md](plan.md) for the full implementation design.
